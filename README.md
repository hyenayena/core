# core

Command REPL for yena (Ink). Also runs one line from the host terminal (see "Running a line from the host terminal"). Commands receive a `CommandContext` (see `src/api.ts` in the host).

## Screen layout: main view and console

- The app is full screen: `main.tsx` renders in the alternate screen (the terminal's own screen and scrollback come back on exit). There is no `<Static>`: `App` keeps the printed lines itself (last 5000) and draws them as a transcript above the main view (or the console prompt), clipped at the top. PageUp/PageDown scroll it by a page, Shift+↑/↓ by a line, unless the side console has the input; while scrolled up a `↓ N newer lines · PgDn or Shift+↓` row shows and new output keeps the view on the same lines. The side panel is the full terminal height.
- At startup `main.tsx` sets the terminal window/tab title to `yena` (OSC 0, only when stdout is a TTY; `src/view/title.ts`).
- The console is the command prompt (with hints, below). With no main view it owns the whole screen, as a plain REPL.
- A main view (e.g. the claude chat) is mounted with `ctx.mount(build)` (target `main`, the default). It then owns the screen and the input, and the console becomes a side panel on the right. Tab opens and closes it when there is nothing to complete: in the console on a line without hints (the editor's `tab` effect, Prompt `onIdleTab`), in a view that passes it on (the claude chat calls `host.togglePanel()` when no suggestion list is open); with hints Tab completes as before, and Shift+Tab never toggles. `§` (what Ctrl+§ sends in most terminals, so it cannot be typed) and Ctrl+T toggle too. Esc does not toggle (since core 0.6.0). Opening focuses the console, closing focuses the main view. Shift+← and Shift+→ move the input between the main view and the open console (host keys: `isHostKey` in `src/view/keys.ts`, views and the console prompt ignore them); ← on an empty console line and a view's `host.move('right')` still work.
- With the panel open, ← on an empty console line moves the input to the main view; a main view moves it back with `control.host.move('right')` (the claude chat does it on → with an empty draft). Both stay mounted; only the focused one reads keys.
- The panel takes 40% of the width by default (at least 28 columns, leaving at least 30); drag its left border with the mouse to resize it (see Mouse), at most 20 rows (rows - 3). Below 60 columns the open console covers the main view instead (it stays mounted, hidden).
- Console commands print into the panel (last 500 lines kept, the visible tail shown) while a main view is shown, into the scrollback otherwise. A command that mounted the main view prints into the scrollback from then on.
- Vim-style `:q` (or `:q!`) as a whole console line closes the side console; when the console is the whole screen it exits the app. A main view can exit the app with `host.quit()` (the claude chat does it on `:q`).
- Mounting a main view clears the transcript (except the welcome line), so a new chat does not show the previous one; a view that resumes a conversation prints its history itself.
- `ctx.suspend(fn)` hands the terminal to a blocking child (an editor, an interactive login): key reading and raw mode are detached, the alternate screen is left, and afterwards the screen is entered again and repainted (`src/view/suspend.ts`); mouse reporting is off meanwhile. `fn` should use `spawnSync`, so nothing renders over the child.
- `ctx.copyToClipboard(text)` writes OSC 52 (base64, so the text cannot carry escapes; at most 50 000 characters; `src/view/clipboard.ts`).
- The `settings` command contributes an `Appearance` tab: title bar colour (Olive, Blue, Teal, Gray, Inverse), colours on/off and Mouse on/off (see Mouse), plus the console width set by dragging (`panelShare`, not in the tab), saved to `<core data dir>/appearance.json` (`src/view/prefs.ts`); `NO_COLOR` still wins.
- A main view may call `host.setTitle(title, detail?)`: a one-row olive bar (#808000, black text; inverse with `NO_COLOR`) above the transcript shows the title on the left (bold, shortened first) and the detail right-aligned (`components/TitleBar.tsx`); both are sanitised; it disappears when the view closes or the title is undefined.
- The hint catalog is rebuilt when the console opens and after every command finishes, so a plugin may change its `subcommands` at runtime (the claude module lists Claude Code commands this way).
- Commands with `autostart: true` run once at startup with no arguments (their output goes to the scrollback); the welcome line then mentions Tab and Ctrl+T.
- `settings` opens a settings screen in the console: one tab per command that declares `settings` (`SettingsTab {title, settings: Setting[], actions?: SettingAction[]}`, choice settings with `get`/`set`; malformed entries are dropped, text is sanitised; a tab with only actions is kept). Actions are listed first as `▸ <label>`: Enter calls `open(control)` and shows its view in place of the list (the screen reads no keys meanwhile); `control.close()` returns to the list and the tabs are read again (`reload`, so a new entry shows up); a view that throws while opening or rendering closes with `Cannot open: <message>`. The action's `control` carries the screen's `host`, `print` and `copyToClipboard`. ↑↓ select, Enter saves the choice and keeps the screen open (`Saved · <setting>: <option>`); ←→ switch tabs (← on the first tab moves to the main view); only Esc or Ctrl+C closes it. The screen gets the whole panel (`host.rows()`) and scrolls to keep the selection (and its label) visible; the hint row shows `· <shown>/<total>` when it scrolls.

## `ctx.mount(build, options?)`

Shows an Ink view in `options.target`: `main` (default) or `panel` (in place of the console prompt).

- `build(control)` runs once, synchronously; the returned element is shown in that area.
- `control.print` prints into that area's output (scrollback for `main`); `control.host` (`ViewHost`) gives `isFocused()`, `columns()`, `rows()` (the panel height less its title, or the terminal height), `subscribe(listener)`, `move(direction)`, `togglePanel()`, `setTitle(title, detail?)` and `isHostKey(input, key)`. A view must read input only while focused (`useInput(..., {isActive})`), lay out in `columns()` and ignore host keys.
- The returned promise resolves when `control.close()` is called (idempotent) or the app unmounts.
- It rejects if that area already shows a view (`A view is already mounted`), `build` throws, or the element throws while rendering.
- With no main view, a `main` mount replaces the console until it is closed.
- The view is wrapped in `MountBoundary` (error boundary): a render error rejects the `mount` promise and restores the prompt.
- A view flushes completed output through `control.print` / `ctx.print` into the transcript and must not render its own `<Static>`.
- `main.tsx` renders with `exitOnCtrlC: false`: at the prompt Ctrl+C exits; inside a view the view receives it. A view that ignores Ctrl+C cannot be interrupted (raw mode); `MountBoundary` only catches render errors.
- Every `.tsx` file imports React explicitly: the host runs tsx from its own root, where the module's JSX settings do not apply.

## Transcript scrolling

The main transcript scrolls by screen rows, not by printed lines: `src/transcript/wrap.ts` wraps every line to the transcript width (colours carried across rows), `src/transcript/scroll.ts` anchors the position to the line at the bottom, so new output, trimming and resizing keep what you read in place. The wheel and Shift+↑/↓ move one row, PgUp/PgDn a page; `↓ N newer lines` counts rows.

## Mouse

`src/mouse/`: `sgr.ts` (tokenizer for mouse reports), `input.ts` (stdin proxy handed to Ink as `stdin`), `terminal.ts` (turns reporting on and off: `ESC[?1002h` + `ESC[?1006h`, presses, releases and moves with a held button), `hit.ts` (areas, wheel step), `view-mouse.ts` (the type views get).

- The `Mouse` setting (Appearance tab, default On, key `mouse` in `appearance.json`) switches it live. Off: no reporting, no events.
- The wheel scrolls the area under the pointer by 1 screen row per event (`WHEEL_ROWS`): the main transcript, or the console panel's output (with a `↓ N newer lines` row while scrolled up). A view under the pointer gets the wheel first (see below); a panel view that does not handle it is not scrolled.
- Dragging the console's left border (the `│` column) in the split layout resizes the panel: a left press exactly on it starts the resize (the border turns cyan), drags move it within the limits above, the release saves the share as `panelShare` (0.1 to 0.9, default 0.4) in `appearance.json`, so it survives restarts and terminal resizes (`panelGeometry`, `shareAtBorder` in `src/app.tsx`). While resizing, nothing else gets the mouse.
- A left click focuses the main view or the panel in the split layout. A click on the console prompt line moves the cursor; a click on a hint item accepts it like Tab (it never runs the line). A prompt click is ignored while keys are still pending render.
- Selecting text (since core 0.7.0): drag over the transcript (the chat history above the chat's input, or the console's scrollback when there is no chat) to select; it is highlighted and copied when the button is let go, and `Copied N characters` shows over the bottom right corner for 2 s. A double click copies a word (letters, digits and path characters), a triple click the whole line. A line printed with `PrintOptions.actions` (`control.print(text, {actions: [{line, copy}]})`, e.g. the chat's code block headers) copies the action's text on a single click on that line of the text instead of starting a selection (`src/transcript/actions.ts`; at most 200 actions per print). A line printed with `PrintOptions.render` (`control.print(text, {render: width => …})`, e.g. the chat's banner) is laid out from `render(width)` for each transcript width (cached per width, `lineText` in `src/transcript/scroll.ts`), so it adapts when the terminal or the console panel changes the width; selection and copying use that text; a render that throws or returns no string shows `text`. Dragging past the top or bottom edge scrolls one row per move. A click or any key clears the selection. The copy is plain text (styles removed), lines joined by newlines, a wrapped line kept whole, trailing spaces dropped, at most 50 000 characters. Logic in `src/transcript/selection.ts` (positions are offsets into a line's text, so the selection survives scrolling and a width change); drags never reach views. The console panel's output and the chat's live area (input, running tools) are not selectable this way.
- Copying goes two ways (`src/view/clipboard.ts`): OSC 52 to the terminal (works where the terminal allows it: iTerm2 needs "Applications in terminal may access clipboard", macOS Terminal has no OSC 52), and, when `YENA_CLIPBOARD_DIR` is set, a file in that folder. `./yena` sets it to `/data/.clipboard` when the host has `pbcopy` (or `wl-copy` / `xclip` with a display), copies each file there to the host clipboard and deletes it (`YENA_CLIPBOARD=off` turns that off). Files are written 0600 under a dot name and renamed, so a half-written file is never copied.
- With Mouse on, the terminal's own text selection needs Shift (Option in iTerm2, Fn in macOS Terminal).
- While Mouse is on, a lone Esc is delivered after up to 10 ms and a trailing `ESC[` after up to 50 ms, in case a report follows. SGR reports are always consumed; X10 reports only while Mouse is on (they look like text); a malformed report is discarded through its final byte; bracketed paste passes through untouched.
- Reporting is turned off on exit (`process.once('exit')`), on unmount and during `ctx.suspend`. After a SIGKILL the terminal keeps reporting: run `reset`.

For module authors: since core 0.6.0 the `ViewHost` also carries `runLine(line)` (starts a console line as if typed there, opening the side console; returns false and runs nothing when the first word is not a command) and `listCommands()` (sanitised `{name, description, usage?}` for hints; since 0.7.0 also `subcommands` with `aliases`, nested as in the console catalog); types in `src/view/view-commands.ts`, feature-detect them like the mouse member. The `ViewHost` core passes to a mounted view carries an optional `subscribeMouse(listener)` at runtime (type in `src/mouse/view-mouse.ts`; not part of the host contract, so feature-detect it and copy the type by structure). Events go only to the view under the pointer, with `x`/`y` relative to the view box plus its `width`/`height`; returning `true` means handled, anything else (a throw included) falls back to core's default. The wheel arrives even when the view is unfocused; a left press focuses the area first. At most 8 listeners per view; nothing is delivered while the setting is off.

Residual risks: verified only with fake TTY streams; the copied text sits on disk in `.yena/.clipboard` for up to 0.3 s when the launcher copies it; SIGKILL leaves mouse mode on; terminals limited to X10 encoding lose clicks at coordinates >= 95.

## Public kit (`src/kit/`)

Other modules may import values and types from core's kit (and nothing else of core's source), each through one adapter file of their own.
- `kit/text.ts` is pure: no React or Ink anywhere in its import graph (`tests/kit/purity.test.ts`). It exports `graphemes`, `cellWidth(grapheme)`, `stringCells`, `truncateCells`, `sliceCells`; `sanitizeText`, `sanitizeBlock`, `sanitizeMultilineInput`; `wrapRows(text, width, {mode: 'word' | 'char'})` and `wrapLines`; `styledCells(text)` (cell width of text containing escape sequences, which take no cells; core 0.5.1); `windowLine`, `indexAtCell`; `windowStart` (`kit/window.ts`, also used by Settings); `inputWindow`, `offsetAtCell` (multi-line input geometry by cells, `…` cut markers); `brailleCells`, `brailleRows`, `brailleText`, `BRAILLE_FILL` (`kit/braille.ts`: one braille cell per 8 dots, filled left column then right, tone worst-wins `del` > `warn` > `add`, unfinished cells show a dim track; `brailleRows` wraps by width and windows rows around a focus cell); `COMMAND_TOOLS`, `formatCommandList`, `formatRunResult`, `CommandToolSpec` (`kit/agent.ts`, see Assistant commands); `tailRows(lines, width, rows)` (`kit/tail.ts`: the last `rows` screen rows of the wrapped lines; when something is cut the first row is `… N earlier lines`, N counting lines not shown in full; with `rows <= 1` the indicator is dropped); and the types `Tone`, `FrameRow`, `PickerItem`, `DotState`, `BrailleCell`.
- `kit/ui.ts` holds the React/Ink parts: `useViewHost` (focus and width of the view's area; inside the app it reads `ViewLayoutContext`, which the app provides around the main view and the panel view, so a view gets a new width in the same frame the console opens or closes; without it, the host subscription), `Spinner`, `useSpinnerFrame`, `SPINNERS` (`squareCorners`, `braille`; `sparkle` and `blink` since core 0.6.0, Claude Code's star and running-tool dot), `ListPicker`, `StatusBar`, `Frame`, `BrailleBar({states, width, maxRows?, focus?})` (braille progress bar; honours NO_COLOR: fail turns inverse, pending dim), `OutputTail({lines, width, rows, title?})` (live output tail: every line goes through `sanitizeBlock`, so SGR is stripped; the optional title takes one row; cut-off indicator as in `tailRows`), `SecretInput({label, onSubmit, onCancel, host?, maxLength?, optional?})` (a hidden one-line input for secrets: shows only how many characters it holds, keeps the value in a ref, never in state or output; control characters of a paste are dropped; Enter submits a non-empty value, or `''` when `optional`; Esc or Ctrl+C cancels; input after either is ignored; default limit 8192), `TextField({label, hint?, initial?, optional?, validate?, onSubmit, onCancel, host?, maxLength?})` (a visible one-line input: typing appends, Backspace deletes, a paste loses its control characters; Enter submits the trimmed value unless it is empty and not optional (`A value is needed`) or `validate` returns a message, shown in red until the next key; the value is kept in a ref too, so a paste followed by Enter submits it; the end of a long value stays in view; default limit 1024) and `colorEnabled`.
- All sanitisers strip every `\p{Cf}` code point (bidi, zero-width, tag characters, U+180E and so on); `sanitizeBlock` and `sanitizeMultilineInput` keep ZWJ. ESC followed by `nF` intermediates is stripped whole, and a C1 ST terminates ESC strings.
- `wrapRows` re-emits only SGR that is already in its input and closes it with a reset; other escapes are zero-width.

## Assistant commands (v0.5.0)

Core gives user and autostart commands a `ctx.commandBridge` (`CommandBridge` from the host `src/api.ts`) so an assistant module can list and run console commands. `src/agent/bridge.ts` (no React) does the work; `app.tsx` creates one bridge per `App`.
- `run({line, caller, confirm?, signal?, timeoutMs?})` never throws; it returns a status: `ok`, `error`, `invalid` (empty, over 4096 characters, any control or format character, or `:q`; lines are rejected, never sanitised), `unknown`, `denied`, `declined`, `off`, `busy` (one agent run at a time, held until the command really settles), `timeout` (default 60 s, clamped to 1 s to 10 min) or `aborted`.
- Policy comes from `Command.agent` / `Subcommand.agent` (`safe`, `confirm`, `deny`). A matching subcommand (name or alias of the first argument) wins over its command; undeclared or invalid values mean `confirm`. `confirm` needs the caller's `confirm` callback to return true; there is no "always allow". Core declares `help`/`echo` safe, `clear`/`exit` confirm, `settings` deny.
- The command runs with a restricted context: `print` (captured after `sanitizeBlock`, at most 24 Ki characters and 600 lines (`src/agent/capture.ts`: the first two thirds and the last third are kept, the middle is replaced by `… [N lines, M characters omitted] …`, so totals and errors printed last survive; the budget stays under the ~25k-token MCP result limit of Claude Code), then `truncated`), `clear`, `exit`, `signal` (aborted on timeout or abort) and `mount`, which accepts only `{target: 'panel'}` (the default target and `main` reject with `Assistant commands can only show views in the console panel`; a non-function `build` rejects with `A view needs a build function`; after the run ended it rejects with `The assistant command has ended`). The view's `control.print` is the run's `print`, so it lands in the captured output. There is no `suspend`, `copyToClipboard` or `commandBridge`, so other view commands fail with their own "needs an interface" error and an assistant cannot recurse.
- Views mounted by an agent run are closed when the run settles; on timeout or abort the signal is aborted first, then the views are closed. `busy` is released only after a settle-time close.
- Console visibility: every executed agent run, and every activity view, opens the console when it is closed and a main view exists (a wide terminal keeps the focus in the chat; below 60 columns the panel takes it). When the last such owner ends and the user has not touched the console, it closes after a 3 s grace period and focus returns to the main view; a new owner inside the window cancels the close. A console that was already open is never auto-closed. Touching means: toggle, moving focus between areas, a click that changes focus, any key while the console has focus, a mouse press or wheel over the console.
- Activity views: any command with `ctx.mount` may pass `{target: 'panel', activity: true}` (`MountOptions.activity` in the host `src/api.ts`). The view is shown in the panel without taking focus and its owner closes it; the Prompt stays mounted but hidden, so the draft survives. `activity` with another target rejects with `Activity views can only be shown in the console panel`; if the panel is busy the mount rejects with `A view is already mounted` and `build` is not called (one panel slot, the first view wins).
- Everything is shown in the console (panel or scrollback): `[caller] > line`, the output and a footer for non-ok results. Agent lines do not enter the history.
- The `Assistant` settings tab (`agentCommands` in `appearance.json`): `policy` (default), `ask` (safe commands also ask) or `off`.
- Log record `agent command` (warn unless ok): caller, command, subcommand, policy, status, confirmed, ms, outputChars, truncated, plus `mounted` and `viewForced` when true; never the line, arguments or output. Debug `view mounted` carries `agent: true` (agent run) or `activity: true` (activity view).
- Kit (`kit/agent.ts`, pure): `COMMAND_TOOLS.list_commands` / `COMMAND_TOOLS.run_command` (neutral `{name, description, inputSchema}`), `formatCommandList(CommandInfo[])` (lists only what the assistant may run; `deny` commands and subcommands are named in one closing line `Not available to the assistant (the user runs them): …`), `formatRunResult(CommandRunResult)`.

## Logging
`App` takes an optional `log` prop (`Logger` from the host `src/api.ts`); `main.tsx` passes `yena.log` (scope `core`). Without it `src/noop-log.ts` is used and nothing is written. Records:
- warn `command failed` {command, err}: the command name and the error only.
- debug `view mounted` {id}, debug `view closed` {id}; warn `view failed` {id, err}.
- debug `unknown command` {unknownCommand: true}: the typed token is not logged.

Arguments and typed input are never logged. Records go to `logs/yena.log` in the host (debug needs `YENA_LOG_LEVEL=debug`); see the host `CLAUDE.md`. Test: `tests/log.test.tsx`.

## Hints

While typing at the prompt (cursor at the end of the line) core lists matching commands, then the subcommands of a known command, under it, with a dimmed ghost completion after the cursor. The data comes from `Command`/`Subcommand` metadata (`name`, `description`, `usage`, `aliases`, `subcommands`) and is validated, sanitised (`sanitizeText`) and capped once in `src/hints/catalog.ts`.

Keys:
- Tab accepts the selected suggestion (a space is appended) and keeps cycling on further presses; Shift+Tab cycles backwards (the first Shift+Tab without navigation takes the last item).
- Up/Down move the selection while the list has items and something was typed; otherwise they browse history. Down on a fresh line and Up with an empty history do nothing.
- Esc: after Tab restores the original text and closes the list; after Up/Down only resets the selection; otherwise closes the list. Up then goes to history.
- Right or End at the end of the line accepts a prefix ghost; otherwise they move the cursor. Home, Ctrl+A, Ctrl+E, Left, Right move the cursor; Ctrl+U deletes to the start; Backspace and Delete both delete backwards.
- Enter runs the line exactly as typed. Only after explicit Up/Down navigation does the first Enter just complete the line (`mod `) and the second run it. After Tab or Shift+Tab, Enter runs the visible line.
- Ctrl+C exits, also with the list open.

Usage row: when a known command or subcommand has `usage`, a dim usage line is shown, and while typing arguments the current placeholder is bold and underlined (`claude ask ` highlights `<text>`; a variadic `<name>…` stays highlighted; flags and positions past the last slot are not). It appears for subcommand lists and, with no items left, as a non-interactive usage-only row (`claude ask `): Tab and the ghost do nothing, Right/End only move the cursor, Up recalls history, Esc dismisses it, a cursor off the end hides it. Commands without `usage` get no name-only row.

Behaviour changes to the original prompt: a long line scrolls horizontally on one row instead of wrapping; the cursor and Backspace work on graphemes; pasted text is sanitised (tabs and newlines become spaces, escapes and all format characters are stripped) and never submits or accepts; the echo of a submitted line is sanitised and collapses space runs; Esc, Tab, Home and End are bound. Command names, aliases, usage and descriptions from plugins are sanitised before display. An unknown command prints `Unknown command: x`, followed by `Did you mean: y?` when a close match exists (typed token of 2 or more characters; distance 1 up to 4 characters, 2 above, or a prefix); `help <command>` shows usage, description and subcommands, and `help <unknown>` fails with `Error: Unknown command: x`.

Layout: rows >= 17 allow 7 hint rows, 11 to 16 allow 4, 10 or fewer allow 2 (never more than rows - 2); extra items become `+N more`; below 20 columns only names are shown, below 8 columns no list. The live frame never exceeds the terminal height minus one row and no line exceeds the width minus one. `NO_COLOR` (non-empty) removes colours; bold, dim, underline, inverse and the `›` marker stay.

Errors: a command that throws prints `Error: <message>` in red, extra message lines indented by two spaces, at most 20 lines of 4096 characters, each line sanitised; a message that cannot be read prints `unprintable error`, an empty one `unknown error`. `registry.find` ignores null or primitive entries and entries whose `name` getter throws; the first match wins.

Not implemented yet (planned only when requested): nested subcommands (`Subcommand.subcommands?` in the host contract, Phase 2a) and dynamic argument completion (`Command.complete?`/`Candidate`, Phase 2b: additive optional members, 150 ms timeout, debounce, sanitised, at most 50 candidates; `claude` would supply `--new`/`--from-file`, `mod` the installed module names). Today `claude auth status|key|…` is not offered.

Manual TTY check:
1. `./yena`. Type `e`: list with `echo`, `exit`, `help`, `clear`, `claude`, ghost, first row marked `›`.
2. Tab accepts `echo `; type `hi`, Enter prints `hi`.
3. Type `ex`, Esc: the list disappears; Up recalls history; Down returns to empty.
4. Type `m`, Down, Enter: the line becomes `mod ` and nothing runs; Enter again runs `mod`.
5. `claude ` shows subcommands and usage; `claude ask ` shows a usage-only row with `<text>` highlighted.
6. `ecoh` Enter: `Unknown command: ecoh` then `Did you mean: echo?`.
7. Type `cl`, Tab, Tab, Shift+Tab cycles; Esc after Tab restores `cl`.
8. Paste a multi-line block and a block with a tab: one line, no flicker, nothing accepted.
9. Resize narrower/shorter with the list open: no wrapping, no stale lines.
10. Type CJK/emoji and move the cursor with Left/Right.
11. `NO_COLOR=1`: the highlight stays readable (underline, marker).
12. Ctrl+C at the prompt exits; inside `claude chat` the prompt and hints are hidden.
13. With the claude module and a credential: the chat opens at startup. Tab (or Ctrl+T) opens the console on the right, Shift+← moves to the chat, Shift+→ back, Tab on an empty console line closes it; double Esc does nothing. In the chat `/project list` runs in the console, `//text` sends `/text` to Claude. PageUp/Shift+↑ scroll the chat transcript. `settings` shows the Claude tab; pick a model, Esc, then `chat` opens a new chat with it (status bar shows the model). Below 60 columns the console covers the chat.

## Running a line from the host terminal

`./yena <console line>` (host script) runs `src/cli.ts --run -- <words>`, which calls the `headless` file named in `yena.json` (`src/headless.ts`, core 0.8.0+): the line is checked like an assistant line (not empty, at most 4096 characters, no control or format characters), looked up in the registry and run with `ctx.headless = true` and no UI (`print` writes sanitized text to stdout; `mount`, `copyToClipboard` and `autostart` are absent). Exit 0 ok, 1 error, 2 unknown command or invalid line. With `request.catalog` (host `src/cli.ts --catalog`, core 0.9.0+) it instead prints the command list for shell Tab completion right after the registry is built and returns: `<command>[ <sub>]<TAB><description>` lines from `completionLines` (`src/hints/catalog-lines.ts`: names `[A-Za-z0-9._-]` up to 64, at most 500 commands and 100 subcommands each, description sanitized to 80 characters). No cache file is written. Tests: `tests/headless.test.ts`, `tests/hints/catalog-lines.test.ts`.

## Tests

`npm test` (`node --import tsx --test "tests/**/*.test.ts" "tests/**/*.test.tsx"`) runs unit tests per `src/hints/` module (`tests/hints/*.test.ts`, shared commands in `tests/hints/fixture.ts`) and drives the real `App` through fake TTY streams: `mountHarness(element, size?, {debug?, tty?, stdin?, stdout?})` in `tests/testkit.ts` (`tty` receives the presses, `stdin` is what Ink reads, e.g. an input proxy over `tty`; `createFakeTty()` / `createFakeStdout(size?)` build them) returns `press`, `settle`, `lastFrame`, `allOutput`, `frameCount`, `resize(columns, rows)`, `unmount`, `raw` (raw-mode log); `fakeLogger` records log calls. `tests/mount.test.tsx`, `tests/log.test.tsx`, `tests/mouse/*.test.tsx` and `tests/hints/*.test.tsx` use it; `tests/mouse/*.test.ts` unit-test the mouse layer. `npm run typecheck` runs `tsc -p . && tsc -p tests`.
